# AI use disclosure

Course: DSA 8401 Applied Machine Learning, capstone project.
This file records how AI assistance was used in this repository, per the course policy.

## Tool

**Claude Code** (Anthropic, model Claude Opus 5.5), used as a coding agent inside VS Code on my
laptop, 19–20 November 2026. It could read and write files in the project folder and run
commands (Python, npm, Docker, git) after I approved them.

## What I did

- Chose the problem and wrote the **project proposal** (1 October 2026): the crisis + five-category
  framing, the cost asymmetry (a missed crisis is far worse than a false alarm), the data plan
  (Strathmore check-ins, augmentation with grouped splits, GoEmotions / AfriSenti / tabularisai for
  intermediate fine-tuning), the model plan (TF-IDF + LR baseline, AfroXLM-R / XLM-R with LoRA,
  DistilBERT comparison), the keyword-OR-classifier safety valve, temperature scaling, retrieval
  instead of generation, the success metrics, and the serving sketch (FastAPI, Docker, ONNX int8,
  React Native, Kenya hosting, DPA 2019).
- Directed the implementation from that proposal and decided on the follow-ups (Docker image,
  app name, GitHub submission).
- Installed and set up the tooling (Docker Desktop, GitHub).

## What the AI tool did

Working from my proposal, Claude Code wrote **most of the code and documentation** in this repository:

| Area | AI-generated |
|---|---|
| Python package `triage/` (data, augmentation, pseudonymisation, safety valve, baseline, LoRA training, calibration, thresholds, evaluation, export, drift) | yes |
| Scripts in `scripts/`, `Makefile`, tests in `tests/` | yes |
| FastAPI service, `Dockerfile`, `docker-compose.yml` | yes |
| React Native app in `mobile/` (UI, API client, offline safety valve) | yes |
| **Synthetic demo dataset** (`data/demo/`) | yes, generated by a script it wrote |
| **Starter Sheng lexicon** (`data/lexicon/sheng_lexicon.yaml`) and name list | yes, a draft, not validated by Sheng speakers |
| **Coping-library text** (`data/library/coping_library.yaml`) | yes, drafted; every entry is marked `approved: false` until counsellors approve it |
| `README.md` and `REPORT.md` (drafted from my proposal and the measured results) | yes |

It also ran the training, evaluation, ONNX export, latency benchmarks and the Docker build.
It found and fixed several problems while doing so; those findings are written up in `REPORT.md`.

No AI model is used **inside** the system at run time to write advice for students: responses are
retrieved verbatim from the library. The optional LLM rephrase step in my proposal was not built.
One input dataset (tabularisai/swahili-sentiment-dataset) is itself LLM-generated, as noted in the proposal.
